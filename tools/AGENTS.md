Existing legacy aim/speed helpers are author-owned, not ABC requirements; newer launch/progression tests use the public update/factory/contact contract instead.

Generated reports, screenshots, test profiles and build products belong in ignored `output/`, `build/` and `dist/`. Keep concise verified results in the wiki.

## Release automation (2026-10-29)

`release_support.py` reads the authoritative version from pyproject.toml. `--tag vVERSION --check` requires an exact version match, HEAD at that local tag (including annotated tags), and a clean tracked/untracked working tree. Without a tag, development builds record the available Git commit and dirty/unknown state without claiming a clean release. Shared helpers check resolved cleanup boundaries, exact inventories and SHA-256 records.

`build.py [--tag vVERSION]` builds Windows x64 only, cleans the previous frozen staging folder, preserves external discovered Paks and writes BUILDINFO.json with the version, commit, toolchain and host source/asset hashes. `package_release.py [--tag vVERSION]` requires matching host build inputs, replaces the entire external Pak tree and cleans build/lib before a wheel build. It checks exact Pak/runtime module sets, source bytes and production assets (including game_over.ogg), plus archive CRC/content. Outputs are `dist/SystemPanic-vVERSION-windows-x64.zip`, the versioned wheel, BUILDINFO.json and SHA256SUMS.txt. Packaging is import-safe; no build starts on import.

`verify_distribution.py --folder FOLDER --wheel WHEEL --output OUTPUT` retains the full frozen drop-in/helper/partial/empty/invalid/Remix probes and isolates user data/preferences in a disposable profile. `verify_release.py [--tag vVERSION]` checks the release checksums/metadata, freshly extracts the ZIP and runs those probes against its actual executable. It also creates a separate venv, installs the wheel with only Pygame as a runtime dependency, checks the installed external content and launches every complete Pak for 240 frames with screenshots. It uses isolated imports, a working directory outside the checkout and disposable user-data roots. `--wheelhouse` permits an offline dependency install. Reports/screenshots stay in ignored output/release-verification; wheel build logs and packaging hashes stay in output/release. These are scripted SDL checks; physical controller, speaker, display and human balance testing remain distinct.

The five release CLIs compile and their help commands pass; importing the packager/verifiers starts no work. Eleven release-safety/test-selection regressions include actual direct entry-point discovery from an unrelated working directory. The integrated Windows build, extracted ZIP, installed wheel and gameplay evidence is recorded in [verification memory](../tests/AGENTS.md#v010-release-automation-2026-10-29) and [the release checkpoint](../docs/releases/v0.1.0-verification.json), separately from final hosted/tagged asset identity.
